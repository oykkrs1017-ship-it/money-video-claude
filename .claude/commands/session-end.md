セッションを閉じる。トークンを使ってよいのは「新しい耐久知」があるときだけ。

入力（任意）: `$ARGUMENTS` = 今セッションの一言要約。空なら git / handoff / 直近差分から推定する。

## やってはいけないこと

- `tasks/lessons.md` を全件読まない。先頭の最新 1 件の見出しだけ見る
- セッション全体を再要約して長文ログを書かない
- 既出の教訓を言い換えて追記しない
- CLAUDE.md / `.claude/rules/` を「念のため」更新しない
- knowledge-keeper サブエージェントを自動起動しない（トークン二重消費）
- コミット・bpush しない（ユーザー指示があるときだけ）

## 手順

1. 決定的ソースだけ読む
   - `git status --short` と `git diff --stat`
   - あれば `.claude/logs/handoff.md`
   - あれば `.claude/logs/sessions/` の最新 JSON（hook が SessionEnd 前に無い場合もある）
   - `tasks/todo.md` の「進行中」セクションのみ
2. 判定（この順）
   - 新しい失敗/回避策が **再現可能な一文** になる → 教訓あり
   - 作業が途中 → handoff だけ更新
   - どちらでもない → 「記録なし」と 3 行で終了。ファイルを触らない
3. 教訓ありのときだけ
   - `tasks/lessons.md` の先頭（`---` の直後）に **15 行以内** で 1 エントリ追加
   - フォーマット:
     `## YYYY-MM-DD — 見出し`
     `**状況**: …`
     `**ルール**: …`
     `**対象パス**: …`
   - 同じ問題が lessons 上で 2 回目なら、ルール昇格を **提案だけ** する。このターンでは書かない
4. 進行中タスクが変わったときだけ `tasks/todo.md` の該当行を更新
5. `.claude/logs/handoff.md` を 20 行以内で上書き（次セッションの入口）

## 応答フォーマット（これ以外を書かない）

```
記録: あり|なし
教訓: <見出し or なし>
handoff: 更新|据え置き
次: <次セッションで最初にやる1手>
```
